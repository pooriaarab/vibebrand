# Mascot system

A method and a small runtime for giving a brand a **character** — not just a
logo. It grew out of the Content Rabbit identity work and is built to be reused:
every brand's mascot is one data file (`<brand>.avatar.json`) that a ~200-line
engine (`mascot/engine.js`) turns into an avatar, a favicon, an expression set,
and an idle animation.

`vibebrand` already generates the token layer — color, type, radius, shadow. This
is the layer above it: the face of the brand.

## The core idea: one geometry, many outputs

The mistake that wastes the most time is drawing the mascot more than once — a
detailed version for the hero, a simplified one for the favicon, separate poses
generated by a text-to-image model. They drift. The favicon stops looking like
the character; six "poses" come back as six different rabbits.

So the rule is: **draw the character once, as data, and derive everything from
it.** The avatar, the 16px favicon, each expression, and the animation are all
the same `parts` rendered differently. Resize it, restyle it, drop it on a dark
page — it stays the same character because there is only one of it.

That's why the format is a JSON spec, not a component. Swap the `parts` for a bat
or a sheep and the expression system, the tile framing, and the animation keep
working unchanged.

## Anatomy of a spec

```jsonc
{
  "viewBox": [0,0,400,400],
  "tilt": -5,                              // whole-character lean, in degrees
  "focus": { "cx":256, "cy":290, "scale":0.92 }, // head centre — frames the favicon
  "palette": { "body":"#f6f0da", "ink":"#161616", "field":"#7857ed", "accent":"#ff5ba8" },
  "parts": [ /* back-to-front paint order */ ],
  "expressions": { "happy":{}, "surprised":{…} },
  "accessories": { "bow":[…], "hat":[…] },
  "animations": { "idle": { "tracks":[…] } }
}
```

Three groups of parts, painted back to front:

1. **Field** — the background the character sits on. Usually the brand color.
2. **Silhouette** — the body. Overlapping shapes that share one fill read as a
   single solid form, so there is no interior linework and no outline to
   maintain. Mark these `"silhouette": true` (the outline and tile features use
   the flag).
3. **Features** — eyes, nose, mouth, on top.

Every part fills by a **palette key** (`"fill": "body"`), never a raw hex, so
restyling the whole mascot is editing four colors.

## Shape language that reads as friendly

These are the moves that made the rabbit look like a character instead of a
diagram. They transfer to other animals.

- **Ears as egg curves, not capsules.** A stadium/rounded-rectangle ear has a
  mechanical top. An egg — a cubic Bézier whose top control points overshoot the
  width (about ×1.2) — gives one fat, round dome. Shorter and wider reads rounder
  than long and narrow. (`earD()` in the lab is the reusable generator.)
- **A slight three-quarter turn.** Cluster the features a little right of the
  head's centre and set one eye a few pixels higher than the other. Perfect
  symmetry looks flat; this tiny offset makes the face feel turned toward you.
- **A whole-character tilt.** Lean the entire mascot ~5°. It costs one transform
  and adds more personality than any single feature.
- **Match feature weight.** Thin a nose or mouth and it looks unfinished next to
  big eyes. Size the nose and thicken the mouth stroke until the three carry
  similar visual mass.
- **Warm body, brand ink, brand field.** A warm off-white body (`#f6f0da`) stays
  friendly against a saturated brand field, and using the brand's own ink for the
  eyes keeps the character on-palette. Cream is worth adding to the token set as a
  named neutral.

## Expressions are overrides, not new drawings

An expression is a small patch on the base parts — turn the eyes into arcs for
"sleepy", swap the mouth ellipse for "surprised". One eye override makes a wink.
Because expressions are data, a brand ships a face for every state (empty,
loading, success, error) without an illustrator drawing each one.

```jsonc
"sleepy": { "eyeL": { "type":"path", "d":"M202 278 q14 13 28 0", "fill":"none",
                      "stroke":"ink", "strokeWidth":7, "rx":null, "ry":null } }
```

Set a property to `null` to remove it — that's how an ellipse eye becomes a path
arc cleanly.

## The favicon is the character, scaled

`renderTile()` takes the same spec, frames it on `focus`, and clips it to a
rounded square or circle. It is not a redraw — so it can never diverge from the
avatar, which is the usual failure mode when a favicon is maintained by hand. It
stays legible down to 16px because the silhouette is simple and it sits on a
solid brand tile.

## Light and dark

A body with no outline disappears when it sits bare on a page whose value is
close to the body color (cream vanishes on white). Two safe patterns, both
theme-independent:

- **Keep it on its tile or disc.** Self-contained, identical in light and dark.
  This is what the favicon and the avatar already do — prefer it.
- **Give it a brand-color outline.** A mid-tone brand color (the purple) reads on
  both light and dark. The engine draws it as a slightly inflated copy of the
  silhouette behind the fill (`outline` option), so it works for any animal
  without knowing the shape.

## Animation without a runtime

The `idle` animation is a few tracks — the body bounces, the ears sway, the eyes
blink — expressed as keyframes over time. `renderIdle()` compiles them to CSS
`@keyframes`, so it plays in any browser with no Lottie dependency, and it honors
`prefers-reduced-motion`. Richer, one-off animations can still be authored
separately; this covers the ambient life a mascot needs everywhere.

## How to build one (the process that worked)

1. **Lab first, ship later.** Put every state — sizes, expressions, accessories,
   placements, light/dark — on one HTML page. You cannot judge a mascot from a
   single hero render.
2. **Hand-draw the vector; don't generate-then-trace.** Text-to-image is great
   for exploring a *direction*, but auto-tracing the result (vtracer and friends)
   produces broken, unusable SVG. Build the geometry by hand once; that is what
   becomes the spec.
3. **Review by looking.** For a visual match, screenshot each state and compare
   against the reference. A text model critiquing pixels it can't see adds noise;
   the reliable reviewer is vision on the actual render.
4. **Iterate the numbers.** Ears too long, nose too thin, tilt too strong — these
   are one or two values in the spec. Change, re-render, look, repeat.

## Using the engine

```js
import { renderAvatar, renderTile, renderIdle } from "vibebrand/mascot/engine.js";
import spec from "./rabbit.avatar.json" assert { type: "json" };

renderAvatar(spec, { expression: "happy", size: 240 }); // hero / illustration
renderAvatar(spec, { accessory: "hat", size: 96 });      // seasonal
renderAvatar(spec, { outline: "#7857ed", showField:false }); // bare on any page
renderTile(spec, { size: 32, shape: "round" });          // favicon
renderIdle(spec, { size: 160 });                         // ambient animation
```

`mascot/rabbit.avatar.json` is the reference spec. To brand a new project, copy
it, swap the `palette`, and reshape the silhouette parts for the animal — the
rest of the system comes along for free.
